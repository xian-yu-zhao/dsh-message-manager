# 会话消息管理 · Session Message Manager

一个本地 DSH 插件：在会话标题栏增加「消息管理」入口，批量选择、删除和恢复模型上下文中的消息。

## 安装

适用于 DSH `0.2.1-rc.2` 及兼容版本：

1. 克隆本仓库：`git clone https://github.com/xian-yu-zhao/dsh-message-manager.git`
2. 在 DSH 的 Plugin Manager 中选择「从目录安装」，指向克隆下来的目录；或执行：
   `dsh plugin --profile desktop add <克隆目录>`
3. 重启 / 刷新 Web GUI，会话标题栏会出现列表图标。

插件是纯 JavaScript 的 Cordis bundle，无需构建或安装依赖。

## 使用

1. 打开任意会话，点击标题栏右侧的列表图标。
2. 「当前消息」中勾选一条或多条，点「删除选中」；也可以点行尾垃圾桶单独删除。
3. 「已删除」中会保留本插件产生的删除记录，可勾选多条后「恢复选中」，或逐条恢复。
4. 删除后，消息会从**后续模型请求**中消失；恢复后重新进入后续模型请求。原始会话日志、聊天记录与审计数据始终保留。

也可以直接使用命令：

```text
/msgmgr list
/msgmgr delete <序号,...>
/msgmgr restore <删除记录序号,...>
```

删除助手消息时，该消息发起的工具调用所对应的工具结果会一并从上下文移除，避免留下没有调用的工具结果。删除工具结果时，其所属的助手消息及同组工具结果会一起移除。

## 删除与恢复何时生效

DSH 的会话格式要求 `developer/message` 必须位于一个已打开的 turn/step 中，且 Session 不能在 `session/event` 派发过程中重入追加。插件据此选择安全路径：

- **消息属于更早的步骤，且当前有步骤打开**：立即从模型上下文移除。
- **会话空闲，或目标属于当前正在进行的步骤**：删除进入内存队列，在下一个 `agent/request` 时、模型请求组装之前同步应用。也就是说，你下一次发送消息时，这条消息不会出现在那次请求里。
- **恢复**：总是进入队列，在下一个 `agent/request` 时应用；用户/上下文消息恢复到原表面位置，助手文本追加到末尾。
- 队列只保存在当前 Host 进程内；如果在下一个请求前重启应用，队列会丢失，删除/恢复记录仍保留，重新操作即可。

## 恢复的能力边界

- 用户消息、普通上下文消息：恢复到原来的表面位置。
- 助手纯文本消息：追加到会话末尾（DSH 不允许 assistant 消息作为带 source 引用的表面替换）。
- 助手工具调用组（助手消息 + 工具调用 + 工具结果）：整组追加到末尾，保持合法的工具生命周期。
- 单独的工具结果、带工具变更的上下文消息、系统提示词：不支持恢复。
- 恢复助手消息会在聊天记录末尾新增一条内容副本；原删除记录仍保留在日志中。

## 行为与限制

- 删除通过追加一个“空 developer 消息”的表面替换实现，符合 DSH 会话日志只追加、可重放的约定；插件只会在已打开的 step 内追加它，避免产生无法重放的日志。
- 聊天视图展示的是历史记录，因此被删除的消息仍会出现在聊天记录里；消息管理弹窗与后续模型请求使用当前表面。
- 系统提示词、尚未落盘的消息（例如正在流式生成的消息）不在可删除范围内。
- 操作需要会话处于运行状态。

## 结构

| 文件 | 作用 |
|---|---|
| `index.js` | Host 半：注册 `/msgmgr` 命令、`message_manager` 工具、批量删除/恢复队列与 `agent/request` 应用器 |
| `core.js` | 纯函数：表面折叠、删除计划、墓碑消息、列表格式化 |
| `client.js` | Client 半：标题栏按钮、批量选择/恢复弹窗、本地表面与删除记录折叠 |
| `cordis.patch.yml` | 网关注入一行插件 |
| `locale/*.json` | 插件管理页的标题与描述 |
